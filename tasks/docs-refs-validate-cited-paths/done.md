# QA Summary: docs-refs-validate-cited-paths

## What Changed

`scripts/docs-refs-check.mjs` previously had an inverted validation gap: a backtick file reference *without* a line number was checked for existence, but any reference *with* a line citation (`:151`, `:10-20`, `:151,254`, `#L10-L20`) was skipped entirely — so adding a line number made a reference *less* validated. A second related bug: comma-list citations like `:151,254` were not recognized as line citations at all, so the suffix was treated as part of the file path and triggered false-positive "missing file" failures on legitimate Codex handoff refs.

Fixing these made the gitignore-skip load-bearing for line-cited refs for the first time, which surfaced a latent third bug: `collectGitIgnoredTargets` passed the entire backtick-token batch to `git check-ignore --stdin -z`, and any path that traverses a symlinked directory (or is outside the repo) causes `git check-ignore` to exit 128. The function treated exit 128 as "empty set," silently disabling the gitignore-skip for the entire run. Two reroute rounds attempted token-shape filtering (dropping whitespace-bearing and flag-like tokens), but empirical investigation showed the only real 128-causers are outside-repo paths and symlink-traversal paths — token shape was the wrong axis. The final fix uses **bisection on exit 128**: split the batch in half and recurse; a single unprocessable path is isolated without affecting its siblings (~225 ms / ~21 `git` spawns vs. the per-path fallback's ~8.2 s / ~977 spawns).

All three bugs are now fixed:

- **Strip-then-validate**: a new `stripLineCitation(target)` helper removes trailing citation suffixes in all recognized forms (single `:5`, range `:10-20`/`:30–40` with ASCII/en/em dash, comma-list `:151,254`, GitHub anchor `#L10-L20`) before the base path is checked. The original full ref text (including citation) is preserved in any finding.
- **Comma-list recognized**: `:N,M` suffixes are stripped; refs that previously triggered a false positive pass when their base file exists.
- **Gitignore-skip resilient**: `collectGitIgnoredTargets` uses bisection on exit 128 to isolate unprocessable paths without poisoning the rest of the batch. A one-time `git rev-parse --is-inside-work-tree` guard short-circuits the whole function outside a git repo (existing behavior preserved).

`isLineCitationTarget` and the symbol-in-file, section `§`, and anchor-link ref handlers are unchanged.

## Files Changed

- `scripts/docs-refs-check.mjs` — added `stripLineCitation`; replaced wholesale line-citation skip with strip-then-validate at both collection and check sites; replaced simple-batch `collectGitIgnoredTargets` with bisection-resilient version
- `templates/scripts/docs-refs-check.mjs` — auto-synced mirror regenerated by the pre-commit hook
- `tests/docs-refs-check.test.ts` — new cases: comma-list citation on existing file passes; missing cited file reports full ref text; gitignore-skip survives a symlink-based 128-causer in the candidate batch; gitignored source file with a space in its name still excluded from scanning; no-repo degradation returns empty set without error

## How to Test

1. In any tracked doc, add a backtick reference to a real file with a comma-list citation (e.g. an existing source file path followed by `:151,254`).
2. Run `npm run docs-refs-check`. Expected: passes — no false "missing file" error.
3. Change the same reference to a path that does not exist (keep the `:151,254` suffix).
4. Run `npm run docs-refs-check` again. Expected: fails with a "missing file" finding that includes the full `:151,254` suffix in the displayed ref — confirming line numbers no longer hide a wrong path.

## Decisions Made

- **Line numbers stay unverified by design.** Only the base file path is checked; cited line numbers are approximate pointers that drift as code evolves.
- **Both collection and check sites strip.** The gitignore-candidate set and the missing-file gate normalize to the same stripped path so the gitignore-skip invariant holds for line-cited refs.
- **Bisection over token-shape filtering.** Two reroute rounds tried to filter "bad" token shapes (whitespace, leading dash) before the `git check-ignore` batch. Empirical measurement showed those shapes do not cause exit 128 — only outside-repo paths and symlink-traversal paths do. Bisection is robust to any future 128-causer without requiring shape prediction, and keeps a single `collectGitIgnoredTargets` implementation used identically by both the source-file pass and the candidate pass.
- **Non-class-1 handlers unchanged.** `isLineCitationTarget` still gates the symbol-in-file, section `§`, and anchor-link handlers; only the bare backtick class-1 path changed.
