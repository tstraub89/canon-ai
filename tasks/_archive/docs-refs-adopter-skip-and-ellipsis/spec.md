# Spec: docs-refs-adopter-skip-and-ellipsis — docs-refs-check: adopter skip paths + ellipsis placeholder

> Written by: Claude | Review by: Codex
> Status: draft

## Problem

Two friction points surfaced during a GP adoption session of canon's `scripts/docs-refs-check.mjs`:

1. **No adopter-extensible skip surface.** GP's prior local validator skipped append-only / frozen / archival doc trees by convention: `docs/archive` (historical specs that legitimately reference deleted files), `docs/personas/reviews` (frozen quarterly reviews), and append-only logs like `docs/task-quality-log.md` that accumulate stale refs by design. canon's gate has no place to express these — the only carve-outs are canon-universal (`docs/BACKLOG.md`, spec.md/plan.md templates, task spec/plan). When canon's stricter gate replaced GP's local script, it flagged 38 broken refs that the prior script had intentionally skipped. The script header (in the file-level docblock) already establishes an "adopters edit this after `canon upgrade`" convention via the `VALID_DIRS` comment, but there is no parallel surface for skip paths. canon's own repo has none of these patterns today, but archive/log carve-outs are a normal adopter pattern.

2. **`...` ellipsis is treated as a real path component.** `isPlaceholderTarget` catches `<placeholder>`, `[placeholder]`, and bare segment names like `path` / `file` / `symbol`, but does not catch the `...` continuation form. A natural placeholder shape an adopter (or canon itself) might write — e.g. ``  `src/...`  `` to mean "files under src" — is currently treated as a real (and missing) file. canon's own `templates/.canon/templates/done.md` happens to use `<path>` so canon does not hit this today; this is defense in depth.

## Decision

Add two improvements to `scripts/docs-refs-check.mjs` (and its parallel `templates/scripts/docs-refs-check.mjs` mirror, since canon-managed):

1. **Adopter-extensible skip surface.** Introduce a new top-level `NOISY_SOURCE_PATHS` constant (initialized to `[]` upstream) near `VALID_DIRS`, with the same "adopters edit this after `canon upgrade`" comment style. Extend `isNoisySourceFile` so that, in addition to the existing canon-universal exemptions, a source file is also exempt when its repo-relative POSIX path either (a) **exactly equals** a (normalized) entry in `NOISY_SOURCE_PATHS` — exact-file match (`'docs/changelogs.md'` skips that file and only that file) — or (b) **starts with `<normalized entry>/`** — directory-prefix match (`'docs/archive'` skips every file under that tree). **Trailing slashes on entries are normalized away before matching**, so `'docs/archive'` and `'docs/archive/'` both work; adopters never have to remember the canonical form. The match expression is `relPath === norm || relPath.startsWith(norm + '/')` where `norm = entry.endsWith('/') ? entry.slice(0, -1) : entry`.

   **Test seam**: `runChecks` gains an optional second parameter — `runChecks(repoRoot, { skipPaths })` — that overrides `NOISY_SOURCE_PATHS` for the duration of the call. The internal resolution rule is `const resolved = options.skipPaths ?? NOISY_SOURCE_PATHS;`. New tests prefer this seam (no module-state mutation, no `try`/`finally`). However, the seam is not enough on its own — an implementation could honor `options.skipPaths` while silently ignoring the module-level `NOISY_SOURCE_PATHS` and still pass every seam-based test, breaking the adopter-facing runtime behavior. To prevent that, `NOISY_SOURCE_PATHS` is also `export`ed, and one dedicated test mutates it (with `finally` restore) and calls `runChecks(root)` with **no options** to prove the default fallback is wired up. All other tests use the seam. The lesson — prefer per-call options over exported-mutable arrays — still applies for new tunables; we keep the export here specifically to verify the fallback path. (`VALID_DIRS`'s existing pattern remains a footgun and should not be propagated for new tunables; QA distills this into `docs/lessons-learned.md`. Retrofitting `VALID_DIRS` is out of scope for this task.)

2. **`...` as a placeholder.** In `isPlaceholderTarget`, add an early explicit `if (target.includes('...')) return true;` short-circuit (placed alongside the existing `<>`/`[]`/`*`/`?` placeholder-character check). This catches `src/...`, `<dir>/.../file.ts`, and any other ellipsis-bearing pattern an adopter might write — broader than only-the-`...`-segment matching, which is the point.

Both edits are mirrored byte-for-byte across `scripts/docs-refs-check.mjs` and `templates/scripts/docs-refs-check.mjs`. (Per the existing canon-ai-dev convention: canon-managed files in `templates/` mirror the root copy, and both must change in lockstep.)

## Non-Goals

- **Not adding any specific paths to canon's default `NOISY_SOURCE_PATHS`.** The upstream array stays `[]`. GP — and any other adopter — fills in their own conventions after `canon upgrade`. Adding GP-specific paths to canon's default would push GP-local conventions onto every adopter.
- **Not reconciling the pre-existing drift between root and `templates/` copies of `isNoisySourceFile`** (the root copy already has extra task/template carve-outs that templates/ lacks). That drift is the in-progress `canon-docs-dedup` task's scope.
- **Not changing the canon-universal exemptions** (`docs/BACKLOG.md`, spec.md/plan.md templates, `tasks/<id>/{spec,plan}.md`). Those stay hard-coded in `isNoisySourceFile` — they are canon discipline, not adopter taste.
- **Not changing `PLACEHOLDER_SEGMENTS`.** The new ellipsis short-circuit is intentionally broader than per-segment matching, so an explicit early-return is more defensible than adding `'...'` to the segment set.
- **Not adding configuration plumbing** (env var, config file, CLI flag). The constant lives in the script; adopters edit the file. This matches the existing `VALID_DIRS` pattern exactly.

## Docs Impact

- No protected doc updates needed in-task. The "adopters edit this after `canon upgrade`" convention is established in-script via the existing `VALID_DIRS` comment; the new `NOISY_SOURCE_PATHS` comment extends that same in-script convention. No protected doc explicitly enumerates the carve-out list — `docs/architecture.md` §Validation only points to the script as a whole.
- **At QA**, distill a lessons-learned entry: prefer **per-call options** (`runChecks(root, { skipPaths })`) over **mutable exported `const` arrays** (the `VALID_DIRS` pattern) for in-script tunables that tests need to override. The mutate-and-restore pattern is a footgun — any test that forgets the `finally` poisons sibling tests; coverage isolation depends on programmer discipline rather than the type system. Per-call options are isolated by construction.

## Known Risks

- **Prefix-match foot-gun.** Because the match rule is `relPath === norm || relPath.startsWith(norm + '/')`, only **whole path segments** match as prefixes — a bare-string entry like `'docs/arch'` would NOT match `docs/architecture.md` (no `/` follows `arch`), and would NOT match `docs/archive/old.md` either (since `docs/arch` is not a full segment of `docs/archive`). That is the intended behavior: the `+ '/'` in the prefix check enforces segment boundaries. The comment example uses full-segment names (`docs/archive`, `docs/personas`) for clarity. The exact-equality branch handles single-file skips (`docs/changelogs.md`).
- **Hidden duplication of canon-universal exemptions.** `isNoisySourceFile` still hard-codes the canon-universal exemptions (`docs/BACKLOG.md`, the template/task `spec.md|plan.md` regexes). An adopter who naively adds `'docs/BACKLOG.md'` to their `NOISY_SOURCE_PATHS` would observe no behavior change, which could be confusing. Acceptable — the canon-universal carve-outs are documented in the existing in-script comment above `isNoisySourceFile` (lines 215–234 of the current root copy), and the new adopter-edit comment doesn't need to duplicate the canon list.
- **`...` over-matching.** Any real path that legitimately contains three consecutive dots becomes invisible to the checker. No such path exists in canon today (verified by grep), and adopters with this in their tree can simply not adopt the pattern. Acceptable: the placeholder convention is more valuable than the edge case of a `...`-bearing real path.
- **New drift between root and templates/.** AC-5's diff-before/diff-after check catches accidental divergence in the new code. The implementer must apply identical edits to both copies; a missed mirror would re-introduce friction the canon-docs-dedup task is trying to eliminate.
- **One mutate-and-restore test reintroduces the footgun for sibling tests.** AC-6 case (e) is the single test that mutates `NOISY_SOURCE_PATHS`. If the `finally` is omitted or the restore is wrong (e.g., `length = 0` not reaching the array because of accidental rebinding), every later test in the file inherits a non-empty default skip list and silently passes assertions that should fail. The case (e) post-restore re-assertion (the second `runChecks(root)` that must report a finding against the same fixture) is the tripwire — it catches a broken cleanup inside the same test, before sibling tests inherit the leak.
