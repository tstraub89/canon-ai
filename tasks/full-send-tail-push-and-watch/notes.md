- spec (rev 3): spec_review rounds 1–2 rejected on the same structural root — subject+path matching cannot prove a commit is canon's. Classified scope-expansion; replaced the predicate class rather than hardening it: canon records each scaffold commit SHA at creation in a git-common-dir record, and the tail pushes only recorded SHAs. Subject/path recognition dropped entirely. Unrecorded pre-upgrade scaffold commits are deliberately not pushed (no heuristic fallback). Unattended choice: record location is git-dir, not a gitignored working-tree sidecar, to avoid a new CANON_RUNTIME_GITIGNORE_PATTERNS entry that un-upgraded adopters would lack.
- spec (rev 4): spec_review round 3 classified edge-fine-tune — it narrows the rev-3 recording mechanism (post-commit `rev-parse HEAD` can capture a concurrent operator commit), no new structural case. Fix: record only a SHA proven by parent + tree match against values noted before the commit; mismatch records nothing (fail closed). Added a forced-interleave AC (post-commit hook in the fixture). Kept `git commit` over `commit-tree` so adopter commit hooks still run; plan may switch with a recorded reason.
- operator (autonomy grant): spec_review rounds 1–3 escalated the scaffold-push guard into SHA provenance recording with temp-index tree proofs. Overruled as scope expansion on the wrong question: the harm is publishing operator source work, not misattributing authorship. Guard reframed as a content-safety rule (exact subject + only tasks/ and telemetry paths + push the checked tip SHA). Operator-made look-alikes that pass are accepted to push. Do not reintroduce provenance tracking.
- spec (rev 6): spec_review round 4 classified edge-fine-tune — stale `record-read` wording left from the dropped provenance design (removed), and rename pre-images escaping the path rule (both sides of renames/copies now count; AC-5 rename variant). Revised the rule rather than adding copy detection: changed paths are read with rename detection off (renames = delete + add, so the outside pre-image still counts); copies need no rule because the source path is unchanged and `tasks/` content is never audited, so detection adds no protection. AC-4 gained a copy case pinning that a copy qualifies. "canon's own" wording in the hint and Human Test Plan replaced with the content rule.
