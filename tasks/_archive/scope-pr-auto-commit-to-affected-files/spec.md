# Spec: scope-pr-auto-commit-to-affected-files — Scope `--pr` auto-commit to spec's Affected Files allow-list

> Written by: Claude | Review by: Codex
> Status: draft

## Problem

`commitHumanReviewFiles()` at [scripts/run-task/main.ts:887](../../scripts/run-task/main.ts:887) is the chokepoint that commits and pushes a task's branch at `--push` / `--pr` time. Its allow-list (`humanReviewAllowedPath()` at [main.ts:637](../../scripts/run-task/main.ts:637)) admits *any* path in `tasks/<id>/**` plus *any* file in `PIPELINE_SHARED_DOCS` ([worktree.ts:24](../../scripts/run-task/worktree.ts:24)) — the union of telemetry and managed docs. The list is path-level and unconditional: a dirty managed doc is allowed in the commit even if this task didn't author the edit.

This is the inert-ifying surface for **cross-pipeline contamination Mode 2** ([docs/BACKLOG.md:454](../../docs/BACKLOG.md:454)): canon's worktree-to-worktree managed-doc sync propagates Task A's edits into Task B's worktree mid-flight. When Task B reaches `--pr`, the foreign content sits dirty in B's worktree, passes the path-level gate, and lands in B's PR — attributing A's work to B and (in the original gallery_wall incident) referencing a file that only exists on A's branch. Detected externally by `docs-refs-check` CI; canon itself emits no signal.

## Decision

Tighten the `--pr` commit allow-list from `{tasks/<id>/**, PIPELINE_SHARED_DOCS}` to `{tasks/<id>/**, PIPELINE_TELEMETRY_FILES, spec.AffectedFiles}`:

- **Task dirs** stay always-allowed (artifact commits at human_review).
- **`PIPELINE_TELEMETRY_FILES`** ([worktree.ts:9](../../scripts/run-task/worktree.ts:9)) stay always-allowed — `lessons-learned.md`, `task-quality-log.md`, `pipeline-invocations.md` are append-only by the orchestrator/QA and aren't the contamination vector.
- **`PIPELINE_MANAGED_DOCS`** ([worktree.ts:15](../../scripts/run-task/worktree.ts:15)) — `architecture.md`, `codebase-map.md`, `decisions.md`, `patterns.md`, `pipeline-orchestrator.md`, `product-context.md` — are no longer auto-allowed. A managed doc is committable only if it appears in the spec's `### Affected Files` table.
- **Anything else dirty AND UNSTAGED** gets warned and skipped (not committed, not failed). "Unstaged" here means `PorcelainEntry.indexStatus` (from `parsePorcelainEntries` at [git.ts:285](../../scripts/run-task/git.ts:285); the value is `line[0]` of `git status --porcelain` output, a literal character not an empty string) is either `' '` (tracked file modified in worktree only — porcelain `' M …'`) or `'?'` (untracked — porcelain `'?? …'`). Today's hard-die behavior at [main.ts:938](../../scripts/run-task/main.ts:938) is downgraded to a warning *for the unstaged + untracked subset only*; the PR opens with the in-scope subset; the operator reconciles the leftover dirty content by hand.
- **Anything PRE-STAGED outside the allow-list** remains a hard die. "Pre-staged" means `indexStatus` is any character other than `' '` or `'?'` (e.g., `'M'`, `'A'`, `'D'`, `'R'`, `'C'`, or the staged half of `'MM …'`). Pre-staging is an explicit operator action — `git add` was run before `--pr` was invoked — and is not the contamination signature (which writes to the worktree, leaving `' M'`). Preserving the die here avoids silently unstaging operator intent.

The Affected Files set is parsed once per `commitHumanReviewFiles()` invocation by reading each task's `tasks/<id>/spec.md`, locating the `### Affected Files` H3 table inside the `## Design` section, and extracting the first column with the same strict grammar as `parseHandoffPathCell()` ([validation.ts:665](../../scripts/run-task/validation.ts:665)). For bundles, the set is the union across tasks.

Additionally, when a dirty managed doc *is* in the union (so it gets committed), print a one-line warning per file inviting the operator to spot-check: `"WARNING: docs/codebase-map.md has uncommitted edits and is in PIPELINE_MANAGED_DOCS — run \`git diff HEAD -- docs/codebase-map.md\` to verify these are this task's work before --ship."` This is the cheap nudge for the same-file-overlap residual (see Known Risks).

The same allow-list change applies wherever `humanReviewAllowedPath()` is consulted today: the dirty-tree filter at [main.ts:938](../../scripts/run-task/main.ts:938), the pre-stage staged-files filter at [main.ts:961](../../scripts/run-task/main.ts:961), and the post-stage check at [main.ts:985](../../scripts/run-task/main.ts:985). The function signature widens to accept the resolved Affected Files set so all three call sites share the new union.

**Three call-sites, three behaviors** (the staged/unstaged partition matters):

- Line 938 (dirty-tree filter): partition `dirtyEntries` by `indexStatus`. Entries where `indexStatus === ' ' || indexStatus === '?'` (unstaged tracked modification or untracked) outside the union → warn and skip (`buildHumanReviewStagePaths` already filters; the warning is operator-facing). Entries where `indexStatus !== ' ' && indexStatus !== '?'` (anything pre-staged: `'M'`, `'A'`, `'D'`, `'R'`, `'C'`, or the staged half of `'MM'`) outside the union → die with today's message. This preserves the contamination-case skip while keeping operator-staged surprises a hard stop.

- **Empty in-scope stage set after warn-and-skip**: today's `stagePaths.size === 0` die at [main.ts:949–950](../../scripts/run-task/main.ts:949) (`"no allowed dirty files found to stage"`) is partitioned by whether any warn-and-skip fired. If the stage set is empty *because* the only dirty entries were warned-and-skipped out-of-scope unstaged/untracked files, `commitHumanReviewFiles()` runs the same push + `reportOrCreatePR` logic the clean-tree retry path at [main.ts:905–932](../../scripts/run-task/main.ts:905) already runs (resolve `branchName` via `git rev-parse --abbrev-ref HEAD`, `git push origin <branch>` with die-on-failure, then `if (createPR) reportOrCreatePR(taskIds, branchName)`), then returns. Push and PR creation are owned by `commitHumanReviewFiles()` internally — the caller only invokes the function and exits, so the empty-stage-set branch cannot delegate them upward. If the stage set is empty because no dirty entries existed in the first place (`dirtyEntries.length === 0`), the existing die at [main.ts:934–936](../../scripts/run-task/main.ts:934) fires unchanged — that path is unaffected.
- Line 961 (pre-stage check via `git diff --cached --name-only`): keep as `die()`. Any pre-staged file outside the union is an explicit operator action and must be reconciled before commit. This is the gate Codex's review flagged.
- Line 985 (post-stage check): keep as `die()`. The post-stage gate is a defense-in-depth assertion that our own `git add` calls only staged union files; firing it is a bug, not an operator-facing UX surface.

## Non-Goals

- **Fix 1 (pre-`--pr` base-drift check)** — separate task, BACKLOG line 460. Catches Mode 1 (third-party commit) and a wider set of Mode 2 cases by diffing against `origin/<base>`. Independent of this fix's surface.
- **Worktree-to-worktree managed-doc sync rewrite** — newly carved-out BACKLOG entry at [docs/BACKLOG.md:467](../../docs/BACKLOG.md). Required for the same-file-overlap residual; intentionally deferred.
- **Hard-fail mode / `--force` escape** — warn-and-skip is the chosen ergonomics. No new flag, no new die path.
- **`autoCommitCode()` (implement-phase commit)** — already scoped via the handoff Changes table at [validation.ts:617](../../scripts/run-task/validation.ts:617). Not touched.
- **Reformatting the `### Affected Files` template or its placement under `## Design`** — parser meets the existing template shape.
- **Changing the spec template to require `### Affected Files`** — parser silently returns `{ files: [], malformed: [] }` for a missing section, missing `## Design`, or missing/unreadable spec file. No special "missing section" warning is emitted by the parser — if the task has nothing in its allow-list and dirty managed docs are present, those dirty files surface through the standard AC-5 unstaged warn-and-skip path with the same operator-facing message. Specs without Affected Files are an existing failure mode (handoff coverage check catches them downstream); not this task's surface.

## Design

### Affected Files

> Any protected doc Claude expects QA to touch (codebase-map, decisions, patterns, architecture, product-context, pipeline-orchestrator) must be listed here. Telemetry files (lessons-learned, task-quality-log, pipeline-invocations) are auto-committed and do not need a row.

- **Same-file overlap residual.** When two parallel tasks both list the same managed doc in their Affected Files (both legitimately edit `docs/codebase-map.md`), the path-level allow-list lets both through. The leaked content from sibling sync still lands in this task's PR. AC-6's advisory warning is the operator's signal to spot-check. The structural fix is the sync rewrite (newly-carved BACKLOG entry). Flag in `done.md` so the human knows the residual exists and what catches it.

- **Spec written before Affected Files convention extended.** Existing in-flight tasks (any task whose spec predates this change) may have managed docs that QA touches but the spec doesn't list. Their `--pr` will warn-and-skip; operator reconciles by hand. Not a regression — the current bug is the opposite shape (over-permissive). Acceptable.
- **Parser-only safety net for malformed Affected Files.** A malformed row (placeholder `` `<path>` `` slipping through review) means the path isn't in the allow-list and gets warned-and-skipped. The malformed warning is the signal. Codex review must catch placeholder rows in spec_review — same discipline as the handoff Changes table. AC-10 surfaces the warning at commit time as a backstop.
- **Downgrading the line-938 die to a warning weakens a today-safety property for *unstaged* dirties only.** Today, an operator with a stray random dirty edit (something they forgot about, not on the spec) gets a hard die that forces them to deal with it. The staged-out-of-scope path (operator explicitly ran `git add`) keeps the hard die — see AC-14 — because pre-staging is operator intent, not contamination. Trade-off is acceptable because the contamination case (unstaged, the bug we're fixing) is materially worse than the unstaged-stray-edit case (the property we're weakening).

Existing fixtures at [tests/run-task-safety.test.ts:1428](../../tests/run-task-safety.test.ts:1428) build temp git repos; extend that pattern.
