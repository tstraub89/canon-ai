# QA Summary: preflight-exempt-telemetry

> Task: Code-review pre-flight exempts pipeline telemetry files from diff coverage check
> QA by: Claude | Date: 2026-05-26

## What Changed

The diff→handoff pre-flight check (`verifyHandoffAgainstDiffFromData` in `scripts/run-task/validation.ts`) now exempts the three pipeline telemetry files — `docs/lessons-learned.md`, `docs/task-quality-log.md`, and `docs/pipeline-invocations.md` — from requiring handoff coverage.

**Root cause of the bug**: On post-reroute implement runs, the cumulative branch diff (`git diff <baseRef>...HEAD`) includes QA's prior-cycle commits to those telemetry files. The validator saw them in the diff but not in Codex's handoff and rejected the handoff as incomplete — even though Codex correctly did not write those files. Codex's workaround was to add misleading handoff rows describing QA's prior work as if it were Codex's. First observed in production on gallery_wall PR #107.

**The fix**: `HANDOFF_DIFF_EXEMPT_PATHS` (previously an empty `Set`) is now initialized with `PIPELINE_TELEMETRY_FILES`, referencing the imported constant by name. No new control flow — the diff→handoff and rename loops already consulted this set. An explanatory comment was added above the constant referencing PR #107 as the discovery vector.

## Decisions Made

- **Exempted only telemetry files, not `PIPELINE_MANAGED_DOCS`**: Managed docs (`docs/patterns.md`, `docs/architecture.md`, etc.) CAN be legitimately edited by Codex when the spec calls for it. Exempting them would hide real handoff gaps. The sibling failure mode (QA editing a managed doc before reroute) is explicitly deferred — see Non-Goals in spec.
- **Widened `HANDOFF_DIFF_EXEMPT_PATHS` rather than adding a new constant**: The constant already existed with the right shape and was already consulted in both loops; no new infrastructure needed.
- **No reverse-direction change**: Telemetry files listed in a handoff but absent from the diff still fail. Spurious Codex claims about telemetry files remain detectable.

## Open Questions / Known Risks

- **Over-exemption**: A runaway implement run that somehow writes to telemetry files would no longer be caught by this pre-flight. Assessed low risk — Codex has never been observed writing to telemetry files in normal operation, and such writes would still appear in the commit log.
- **`PIPELINE_MANAGED_DOCS` sibling case unaddressed**: If QA appends to `docs/patterns.md` before a reroute, the next post-reroute implement run will see the same false-positive failure pattern. If this recurs, the next step is either expanding `HANDOFF_DIFF_EXEMPT_PATHS` or adopting the implement-baseline-SHA mechanism (explicit Non-Goal here).
