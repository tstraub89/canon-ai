- [plan] Live check (gh 2.89.0, this session): gh fills `{owner}` inside the endpoint's query string (`pulls?head={owner}:<branch>`), and `--paginate --slurp` returns an array of pages. `GET repos/{owner}/{repo}` returns the `allow_*` booleans.
- [plan] Interpretation: the draft-PR create sends its JSON payload with `--input <tmpfile>` (the spec allows either form). The commit-subject fallback is `- <subject>` lines, oldest first. If `git log` fails, the PR still opens with an empty body and a warning.
- [plan] Interpretation: the guard passes `--hostname` whenever a URL or a `-R HOST/OWNER/REPO` value names a host, including github.com. This covers the spec's "for a non-default host" and more. An unrecognized `-R` shape fails open.
- [plan] Branch lookup also checks `base.ref` in code, on top of the `base` query param (defense in depth). The test fakes must emit `base.ref`.
- [implement] The REST listing asks for `state=closed` for both merged and unmerged closed PRs; the forge distinguishes them from `merged_at`, so test fakes must return that field rather than inferring merge state from the query alone.
- [implement-revision] A host-qualified `gh -R HOST/OWNER/REPO` value supplies both the REST host and repository path; forwarding only `--hostname` can make a safety lookup inspect a different repository and fail open.
- [plan] Reroute 1: forge host comes from a new `setOriginUrlReaderForTest` seam, kept separate from `gitLogRunner`. Forge tests stub it to "no origin" by default, because otherwise canon-ai's own github.com origin leaks `--hostname` into the existing argv pins. AC-15 forge red-first runs on `bd37a01` plus a seam-only stub (the reader is stored, never used); without the stub the import fails for the wrong reason.
- [plan] Reroute 1 interpretation: guard `-R OWNER/REPO` (no host) passes no `--hostname` (gh's own `-R` semantics). Only the no-`-R` cwd fallback uses the origin host. A whitespace-only `-R` counts as absent. A `-R` with a host must have exactly OWNER/REPO after it; anything else fails open with no read.
- [plan] Follow-up candidate for QA: `main.ts` `parseOriginRepoSlug` URL fallback is github.com-only; it predates this task and is outside the amendment's scope.
- [implement-reroute] `gh api` resolves `{owner}/{repo}` separately from its API host. Pin `--hostname` from the `origin` URL on each forge call; keep the placeholder slug so gh's set-default repo selection remains intact.
- [implement-reroute] For guard numeric lookups, a non-empty malformed `-R` must skip the REST read entirely; falling back to `{owner}/{repo}` can inspect PR N in the wrong repository. Empty `-R` is treated as absent and uses the cwd repo.
- [implement-revision] With `gh api --paginate --jq '.[]'`, successful empty PR listings produce empty stdout; the forge treats that as `none`, while malformed non-empty lines remain `unreadable`. The fakes emit one JSON object per line to match gh's filtered pagination output.
- [implement-reroute] Amendment Round 2 requires an offline `gh auth token --hostname` probe, which is the stated exception to AC-1's “api first” wording. It shares the single `runCommand('gh'` site; only API calls use the `api` subcommand. The forge caches both successful and failed host probes per process, and test runner/origin setters clear that cache to prevent cross-test state leakage.
- [implement-revision] gh expands its legacy `:repo` placeholder in query strings as well as `{owner}` placeholders. The PR head filter therefore percent-encodes its separator (`%3A`) so branch names such as `repo-x` remain exact; the guard uses path endpoints without this query form.

Newest amendment wins: the probe goes through the same forge `runner` seam (still one `runCommand('gh'` in src), reads only the exit status, and discards the token. Spec not edited.
- [plan] Reroute 2: forge caches the auth-probe result per normalised host for the process; both test setters clear it. The guard (one process per hook call) probes uncached with `stdio: 'ignore'` so the token is never captured. Explicit `-R`/URL hosts are normalised but not probed.
