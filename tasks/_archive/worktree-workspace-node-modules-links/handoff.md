## Intent & Rationale

Worktree creation now discovers eligible npm workspace directories from the supervising checkout, links each installed workspace `node_modules` into the task worktree, and repairs only missing workspace links on later entries into canon's registered worktree. Workspace resolution and source/destination safety use shared helpers in `scripts/run-task/worktree.ts`; both source and destination containment realpath their operands and fail closed.

The QA and human-review gates reuse the same resolver, containment helper, and explicit-target probe. Only untracked symlinks verified against the corresponding supervising-checkout install are exempt. The workspace exemption is disabled when the active checkout canonicalizes to `REPO_ROOT`. At human review, one normalized classifier drives both allowlisting and stage selection: after verified links are removed, every remaining dirty path whose final segment is exactly `node_modules` is rejected, while files beneath vendored `node_modules` directories remain eligible for an authorized directory prefix.

## Human-Review Amendment

## Edge Cases Considered

- Recursive globs over plain files, non-package directories, and `node_modules` interiors.
- Lexical `..`, source symlink escape, destination symlink escape, dangling paths, and path-prefix siblings such as `wt`/`wt-evil`.
- Hoisted installs, missing worktree workspaces, regular files/directories, wrong-target links, concurrent link creation, and missing-only rerun repair.
- Git C quoting, `core.quotepath=false`, Unicode normalization, literal ` -> ` in untracked paths, staged links, and N simultaneous exemptions.
- Directory-form staging beside ignored real installs, verified symlinks, and vendored dependency files.
- Worktree-disabled runs where candidate/expected workspace probing would otherwise be tautological.
