# Spec: push-upstream-tracking — Set upstream tracking on task-branch push

> Written by: Claude | Review by: Codex
> Status: draft | reviewed | approved | implemented

## Problem

When canon pushes a task branch at `human_review` (`--pr` / `--push`), it uses a bare `git push origin <branch>` at both push sites — [`scripts/run-task/main.ts:1117`](../../scripts/run-task/main.ts) (clean-tree retry path) and [`main.ts:1215`](../../scripts/run-task/main.ts) (dirty-tree commit-then-push path). Neither sets the upstream tracking ref.

Consequence: the local task branch in the worktree never tracks `origin/<branch>`. So:

- `git status` in the worktree cannot show ahead/behind ("Your branch is up to date with 'origin/…'") — it reports no upstream, leaving the operator unable to tell at a glance whether local commits are pushed.
- Bare `git pull` / `git push` (no args) fail in the worktree with "no upstream configured," forcing the operator to spell out `git push origin <branch>` every time.

This makes the post-`--pr` manual-git workflow (inspecting state, pulling a CI fix, re-pushing) more cumbersome than it needs to be.

## Decision

Push the task branch **with upstream tracking set** (`git push --set-upstream origin <branch>`, i.e. `-u`) at both `human_review` push sites, so the local branch tracks `origin/<branch>` after the first push. Setting `-u` is idempotent — re-running when the branch already tracks origin is a safe no-op that just re-affirms the tracking ref — so it is safe on every `--pr`/`--push` invocation, including the idempotent retry path.

## Non-Goals

- No change to *what* gets committed or pushed, to the base-drift gate, or to PR creation/reporting.
- No change to push failure handling (the existing `die(...)` on push failure is preserved).
- No automatic `git pull`/fetch/rebase behavior — this only establishes the tracking ref; it does not change canon's sync logic.
- Not touching the `--ship` merge path or any non-`human_review` git operation.

## Acceptance Criteria

- [ ] AC-1: The push at the clean-tree `human_review` path (`main.ts:1117`) sets upstream tracking (`-u` / `--set-upstream`). Verify by inspecting the `git push` argument vector in a unit/integration test or by post-push tracking-ref assertion.
- [ ] AC-2: The push at the dirty-tree commit-then-push path (`main.ts:1215`) sets upstream tracking. Same verification.
- [ ] AC-3: After `canon run <id> --pr` (or `--push`), `git -C <worktree> rev-parse --abbrev-ref <branch>@{upstream}` resolves to `origin/<branch>` — the tracking ref is established.
- [ ] AC-4: After the push, `git -C <worktree> status -sb` shows the branch tracking origin (header line of the form `## <branch>...origin/<branch>`).
- [ ] AC-5: Idempotent — re-running `--pr` when the branch is already pushed and already tracking origin succeeds with no error (the `-u` flag is a safe no-op on an already-tracking branch). Verify by running `--pr` twice in a row.
- [ ] AC-6: No regression to push-failure handling — a failed push still triggers the existing `die(...)` path with its message intact.

## Design

### Affected Files

| File | Change |
|---|---|
| `scripts/run-task/main.ts` | Add `--set-upstream` (`-u`) to the `git push` argument vector at both `human_review` push call sites (≈ line 1117 and ≈ line 1215). |
| `dist/scripts/run-task.js` | Regenerated by `npm run build` (bundles `scripts/run-task/**`). |
| `tests/run-task-safety.test.ts` | Fake-git harness asserting the `-u` arg vector at both push sites (AC-1, AC-2). |
| `tests/run-task-ship.test.ts` | Repurpose the `--push` artifacts-commit test into a `--pr` real-git test that verifies the upstream tracking ref resolves to `origin/<branch>`, the `status -sb` tracking header, and idempotent re-run (AC-3, AC-4, AC-5). |

> Mechanics deferred to implement: exact flag placement in the `gitSafeAt(cwd, 'push', …)` arg array. Both sites currently call `gitSafeAt(cwd, 'push', 'origin', branchName)`; the change inserts `--set-upstream` (or `-u`) before `origin`.

### Interaction Dependencies

- Both push sites share the same `gitSafeAt` wrapper and the same failure-handling (`die`) contract — apply the flag consistently to both so the tracking behavior doesn't depend on which path ran.
- The idempotent `--pr` retry contract (push runs even when an open PR exists, per the comment at `main.ts:1102–1115`) is preserved; `-u` does not change push idempotency.

### Data Model Changes

None.

## Known Risks

- **`-u` on an already-tracking branch**: a no-op that re-affirms tracking; safe (AC-5).
- **Force-updated origin ref**: `-u` simply (re)points the local tracking ref at `origin/<branch>`; no data loss, matches operator expectation.
- Low blast radius overall — a single flag added to two push invocations, no logic-flow change.

## Human Test Plan

1. Take a task to the review-ready state and open its draft PR (`canon run <id> --pr`).
2. In the task's working folder, check version-control status. **Expected:** it now reports the branch is tracking its copy on the server (e.g. "Your branch is up to date with 'origin/…'"), instead of saying there's no upstream branch.
3. From the working folder, run a plain pull and a plain push (no branch name typed). **Expected:** both work without "no upstream configured" errors.
4. Re-open the PR command a second time. **Expected:** no error; everything still works.
