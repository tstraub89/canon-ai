[spec_review] The metrics writer's `safeCell` is not a general round-trip serializer for the header-keyed parser: it escapes `|` but not a preceding backslash, while `splitTableLine` uses odd/even backslash parity. A focused parse of the supplied value `a\|b` after `safeCell` recovered only `a\` in the target cell because the doubled backslash made the pipe a delimiter. Any reusable table writer must serialize against the parser's actual escape grammar rather than copy `safeCell` literally.

[spec_review round 4 → revision] Shape Check "(no concerns)" a second time; both blocking items narrowed AC-4c and AC-4 — the same cases round 3 opened, now demanding precision. (1) "preserve judgment cells from the surviving record" never said WHICH record survives when duplicates disagree; four readings all satisfied the wording and produce different summaries. Fixed with an explicit per-cell precedence table: `Spec verdict` = EARLIEST non-empty (the schema defines it as the first verdict, so latest-wins would destroy the column's meaning), all other judgment + adopter cells = LATEST non-empty (corrigible judgments), ordering by document position (chronological for an append-only log). (2) Real data-corruption path found: citing metrics.ts `safeCell` was insufficient — it escapes pipes but NOT backslashes, while `splitTableLine` (markdown-table.ts:1-33) treats a pipe as escaped only after an ODD backslash run. Verified: Notes value `a\|b` -> safeCell -> even backslash run -> parser splits on that pipe -> cell truncates to `a\`. Serialization is now bound to a round-trip contract against splitTableLine with a backslash-before-pipe regression fixture. (The same latent gap in safeCell itself is out of scope — pipeline-invocations cells are model names/statuses, not free prose.)
