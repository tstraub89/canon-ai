[spec_review] `CANON_TASKS_DIR_OVERRIDE` is load-bearing inside the existing first-worktree `ensureBranch` tests: the bundle-heartbeat fixture expects branch writes in the override root even while it constructs a fake worktree. Any direct-path bootstrap write needs an explicit override-preserving branch rather than bypassing `statusFileFor` unconditionally.

[spec_review] The leader's worktree `branch` doubles as the durable bootstrap-complete signal: `runImplementPhase` and `ensureBranch` both skip first-implement work once that leader field is non-empty. A multi-member bootstrap must therefore write the leader last or repair all members on the reuse path, otherwise a mid-loop exit strands blank secondaries.

[spec_review] `ensureBranch` validates bundle members' `worktree` flags but has no equivalent secondary-branch consistency check. A reuse-path repair that only fills empty branches leaves a non-empty stale branch untouched, so the resolver's content/branch match can still reject the intended worktree and fall back to main.

[spec] Round-2 revision (revision 2). Resolved all 3 blocking findings within the existing design shape (core scan + resolver-free override-aware bootstrap write held both rounds — Codex: "core shape is sound"). (1) Crash-consistency: change 2 now writes secondaries first + leader last (the "done" marker), and NEW change 3 repairs any blank member on the reuse path (`git.ts:262-269`) — did BOTH of Codex's either/or options since they cover different paths (leader-last narrows the first-implement window; reuse-repair guarantees the post-condition where a stranded secondary would otherwise be permanently skipped). Pinned by deterministic state-fixture test AC-2 (no nondeterministic process kill). (2) Match rule now requires the candidate's own `worktree === true` (AC-4 + AC-5(c)). (3) Present-but-unreadable candidate is now fail-closed `die`, distinct from absent-candidate skip (AC-4 + AC-5(f)); atomic `writeStatusToFile` means it fires only on genuine corruption. Iteration-shape read: this is edge-hardening of a delicate `resolveTaskCwd` path, not scope-expansion. TRIPWIRE for round 3: a NEW failure *class* (not another tightening of gating/fail-closed/crash themes) → redesign/resize rather than iterate.

[spec_review] A non-task doc edited during spec authoring is not absorbed by `commitTaskArtifactsToBase`; unless reverted before implement or recreated later inside the task worktree, the first-worktree dirty-source guard aborts on it. The current deferred-follow-up entry in `docs/BACKLOG.md` exposed this boundary.

[spec_review] Candidate status ownership must distinguish syntactic JSON readability from schema validity. `readStatusFromPath` already rejects non-string branch fields without re-entering `resolveTaskCwd`; bypassing it with a raw cast can turn corrupt-but-parseable metadata into a zero-match fallback to main.

[spec_review] `resolveTaskCwd` is below repeated status/artifact helpers and the heartbeat directory resolver, so a subprocess-based secondary scan repeats per resolution rather than once per phase. Any performance assessment should measure that actual call pattern and avoid an uninvalidated cross-phase cache.

[implement] A real-git worktree path on macOS is reported canonically under `/private/var` even when `os.tmpdir()` supplied the `/var` alias. Routing assertions that compare fixture paths should normalize with `fs.realpathSync`; otherwise correct worktree resolution fails only on path spelling.
