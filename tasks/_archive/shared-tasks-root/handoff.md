## Intent & Rationale

Task enumeration, scaffolding, doctor checks and template lookups now resolve against the main checkout root. Per-task status reads and writes continue to use the existing `resolveTaskCwd()` routing. `canon task` now refuses outside git before dispatching a subcommand, matching the human amendment and avoiding a non-git fallback in worktree resolution.

## Deviations from Plan

None. The legacy single-field git query fallback from the initial implementation was removed as required by amended AC-17; fake git now answers the combined query used by production.

## Edge Cases Considered

- Canonicalized git-dir/common-dir comparison handles macOS path aliases.
- Separate-git-dir main working trees use `--show-toplevel`; linked worktrees of separate-git-dir and submodule checkouts remain unsupported as specified.
- Git probe errors take the non-git path; task dispatch then refuses before filesystem changes.
- Invalid task names and regular files are skipped by shared task scans.
- Empty `CANON_TASKS_DIR_OVERRIDE` is treated as unset; relative overrides resolve against cwd.
- The task-entry predicate checks both id validity and directory type.
