# Completion Summary: watch-late-attach-crash — Late watch attach reports a crashed run as death

> For the human. This is what you need to know.

## What Changed

When `canon watch <id>` starts after a detached run has already crashed, it now says so. Before this change, a crash that happened after a phase transition (for example, an auto-commit failure after implement finished) was reported as "nothing to watch" with exit code 2, or as a generic "run `canon run <id>` to resume" death with no reason. Watch now checks the same crash evidence the idle path already used: a dead orchestrator pid left behind, or a fresh non-zero exit marker in the run log. If that evidence exists, attach reports `death` with exit code 4 and prints the failure reason and the resume command. If there is no evidence, attach behaves as before. Clean exits and stale markers still report "nothing to watch".

## Files Changed

- `src/cli/commands/watch.ts` — shared crash-evidence helper (`findCrashEvidence`) used by both the idle and attach classifiers; attach `death` carries an optional reason; the death reporter prints it.
- `tests/watch.test.ts` — red-first regression for the late-attach miss, plus boundary tests (no evidence, clean marker, stale marker, in-progress with and without evidence, and an end-to-end `watchCmd` exit-4 check).
- `docs/pipeline-orchestrator.md` — exit code 4 row now says the crash evidence applies whether watch attached before or after the run exited.
- `templates/docs/pipeline-orchestrator.md` — mirror of the doc change, generated by `npm run sync-templates`.
- `dist/cli/index.js` — rebuilt bundle (committed with the source change).

## How to Test

1. Start a full-auto run on a scratch task and make the planning step fail (or kill the orchestrator) without watching it.
2. After it stops, run `canon watch <task-id>`.
3. Expected: the watcher reports that the run crashed, shows the failure reason and the `canon run <task-id>` resume command, and exits with code 4. It does not say "nothing to watch".
4. Watch a task whose last step finished cleanly.
5. Expected: still "nothing to watch", exit code 2.

## Proposed Changelog

- **`canon watch` reports a run that crashed before watch attached as a crash.** When you start watching a detached run after it has already died, watch now prints the failure reason and the `canon run <id>` resume command and exits with code 4. Before, it reported "nothing to watch" (exit 2) when the crash came after a phase had finished.

## Decisions Made

- **Attach reuses the idle path's evidence check unchanged.** The freshness tolerance, marker parser, and candidate directories are the same. Only the call site is new. The spec's non-goals rule out changing them.
- **`human_review` is excluded from attach-time crash evidence.** The spec says `human_review` handling on attach is unchanged, so a fresh crash marker while `human_review` is pending does not produce `death`. This is an interpretation of the spec's non-goal, recorded in `notes.md` and in `handoff.md`'s Blockers as an `[ambiguity]` entry. It is not a contradiction.
- **Attach `death` carries a reason but no pid.** The spec specifies a reason and the resume hint only. The stdout summary line is unchanged (`state=<state> reason=death`).
- **The helper takes the already-computed pid liveness** instead of probing again (a deviation documented in `handoff.md`). No AC is affected.

## Open Questions

- **Known Risks gap (review nit).** Attach-time evidence does not require a previously completed phase, unlike the idle path. So a leftover fresh non-zero marker on a first-phase `pending` task now reports death. The spec asks for exactly this, so the code matches it. The false-positive direction is not written into Known Risks. Decide whether to add it there or accept it as is.
- **Bundle secondary, late attach.** Still reports "nothing to watch" with no heartbeat, as the spec's Known Risks already records. Not fixed here.
- **Untested attach edges (review nits).** No attach-level test covers a dead resolved pid, heartbeat-primary candidate selection, a fresh marker under `human_review`, or a `changes_requested` phase. Shared code paths are covered elsewhere. Add tests in a follow-up if you want them.
- **Redundant helper parameter (review nit).** `findCrashEvidence` takes both `probeAlive` and `resolvedPidAlive`, and both callers pass the latter, so the fallback probe is dead code. Harmless; clean up when convenient.
